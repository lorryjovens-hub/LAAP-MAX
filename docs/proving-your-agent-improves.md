# 如何证明你的 Agent 在变好

> 一个关于记忆、可证伪预测与验证账本的方法论。
> 首发数据：2026-08-02，LAAP 记忆系统基线。

---

## 开篇：两个数字

2026 年 8 月 2 日，我们给自己的记忆系统跑了一次诚实的体检。

20 条事实，10 个主题域，写入一个真实的生产记忆库（6500+ 条记录），然后用自然语言提问的方式逐条召回——不背答案，不猜结果，每条检索 query 都与原文措辞不同。

结果：**25%。** 在隔离的干净环境里重跑：**10%。**

也就是说：当你以"记得内容大意"的方式去问一个记忆系统，它每问四到十次，才有一次能找到你要的东西。这就是当前主流记忆检索（LIKE 子串匹配）的真实水平。

这个数字不好看。但我们把它公开了——因为它是真的，也因为**它是我们能证明的第一件事**。

## 问题：Agent 部署之后，没人能回答"它在变好吗"

过去一年，Agent 从演示走向生产。但有一个问题始终悬在所有团队头上：

> **你的 Agent 这周比上周强吗？强在哪？你怎么知道？**

多数团队的答案分三种：

1. **"感觉变强了"**——基于个别案例的体感，不可复现，无法审计。
2. **"benchmark 涨了"**——但 Ilya Sutskever 说过一句狠话：*"真正的奖励黑客不是模型，是设计基准和 RL 环境的人类研究员。"* 刷榜刷出来的分数，到了陌生场景就露馅。
3. **"跑通了就算强"**——把"能完成任务"误当成"在持续进步"。任务完成率是存量，进步是增量。

行业里最接近正确答案的是两件事：Anthropic 的研究闭环（Claude 写了自己代码库 80% 的合并代码，一周关掉 97% 的基准差距），和 AIDE²（8 天无人监督的自动研究循环，产出的 Agent 打败了人类调了两年的版本）。它们的共同点：**每一轮改进都有可验证的证据**。

但大多数团队做不到这一点。不是不想，是没有方法论，也没有工具。

## 方法论：四段式，让"变好"可证伪

我们给出的答案是四段式流程，它只有一个目的：**让每一次改进都携带一个可以被证明错误的预测。**

### 第一段：PROPOSE——每个改进必须自带预测

任何改动——换检索算法、调 prompt、加记忆模块——在动手之前，必须回答三个问题：

- **预期效果是什么？**（claim：一句人话）
- **用什么指标衡量？**（metric：可量化，如 recall_rate）
- **达到多少算成功？**（threshold + 方向：如 ≥ 0.60，越大越好）

没有预测的改进，不允许进入流程。这条规则的价值在于：它把"我觉得这能行"翻译成"我预测这能把指标从 0.25 推到 0.60"。

### 第二段：VERIFY——客观评估，与改进者无关

预测必须由**循环之外**的评估器验证。我们的评估器是一个开源基准协议（recall-bench），它的核心设计是"唯一标记协议"：

- 每条测试事实携带一个唯一标记（如 `RB_20260803_07`）；
- 检索 query 是自然语言改写，**标记绝不出现在 query 里**；
- 命中判定：标记是否出现在检索结果中。

这个协议保证了三点：**客观**（不需要 LLM 裁判，不靠主观打分）、**防污染**（query 不含标记，测不到字符串复制）、**可复现**（任何人拿同一协议跑同一后端，得到同一数字）。

### 第三段：RECORD——账本，append-only，可审计

每一条预测和验证结果写入 append-only 账本：预测时记录 claim/metric/threshold/baseline，验证时记录 actual/evidence/verifier。账本不可修改，只能追加——**改进的历史变成证据链，而不是聊天记录**。

### 第四段：循环——账本回喂系统

账本统计出三个成绩单指标：

- **hit_rate**（验证通过率）——你的预测准不准；
- **verification_rate**（验证覆盖率）——你有没有真的去验证；
- **avg_delta**（平均变化量）——改进到底带来了什么。

这三个数字回答三个问题：*你的团队对系统的理解对不对？你的纪律够不够？你的努力有没有用？*

## 案例：我们自己的第一个闭环

方法论不是空谈。我们用它给自己做了第一次体检（就是开篇那两个数字），并且把体检工具做成了开源包。

当前状态（写本文时）：

| 指标 | 数值 |
|------|------|
| recall（生产库，LIKE 检索） | 25.0% |
| recall（隔离环境，LIKE 检索） | 10.0% |
| 预测账本 | 刚开张，0/0 |

诚实地说：账本还是白的。但方向已经立住了——**下一个改进（引入语义检索）将被登记为一条可证伪预测：*"recall 从 25% 提升到 60% 以上"*，然后由独立评估器验证，结果无论是 61% 还是 32%，都会写进账本。**

这就是"证明 Agent 在变好"的全部含义：**不是宣称，是记录；不是感觉，是数字；不是最终结论，是可证伪的每一步。**

## 三个层次的成熟度

| 层次 | 特征 | 例子 |
|------|------|------|
| **跑分** | 有 benchmark，但可能过拟合 | "我们在 HumanEval 上 92 分" |
| **闭环** | 改进自带预测+验证 | "我们预测 recall 到 60%，独立评估器验证通过" |
| **账本** | 闭环持续运行，历史可审计 | "过去 30 天 24 条预测，20 条验证通过，avg_delta +0.08" |

大多数团队在第二层和第三层之间卡住，不是因为技术，是因为**纪律**——预测要写下来，验证要独立跑，结果要认账。这四段式流程的全部价值，就是把纪律工程化。

## 收尾：你的 Agent 在变好吗？

下次有人问你这个问题，不要回答"我感觉它变强了"。

写下预测。跑独立评估。记入账本。然后——用一个数字回答他。
