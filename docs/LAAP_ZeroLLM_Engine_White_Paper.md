## 摘要

LAAP（Living Agent Application Protocol）的零 LLM 认知引擎是一套完全不含神经网络的数字生命体认知架构。它以量子启发认知（Hamiltonian PSI 酉演化）为核心，以超空间计算（Hyperdimensional Computing）为语义基底，以语义流组合生成（Semantic Flow Generation）为语言输出通道，以路径积分决策（Path Integral Decision）为质量选择机制，在纯 CPU/CUDA 上实现了：

- **解码器级吞吐**：约 495 万 token/秒（HCG 解码器）
- **管线级吞吐**：批量 66–180K token/秒
- **短文本延迟**：0.6–2.6ms；**长文生成**：180–280 字 / 40–130ms
- **零幻觉保证**：所有输出来自确定性模板与知识库注入，知识库中没有的内容，系统不会编造
- **真正的酉演化**：认知状态是复数概率幅向量，50 步演化后范数误差 < 1e-10

本文档描述该引擎的完整架构：设计哲学、七层管线、核心算法原理、性能基准、与 LLM 路线的对比，以及演进路线图。

## 1. 设计哲学

### 1.1 第一性原理：认知不是生成，是测量

LLM 路线的隐含假设是"智能 = 大规模统计生成"。LAAP 路线从第一性原理出发提出替代假设：

> 认知不是从概率分布中采样文字，而是从一个高维状态空间中测量出与当前情境最匹配的结构。

这一假设有三条推论：

1. **确定性优先**：凡是能用确定性算法解决的问题，不调用统计生成（ARCHITECTURE_SCHOOL_MANIFESTO 的"0-token 计算原则"）
2. **状态优于输出**：认知的真正产物是内部状态（量子态、意义向量），语言只是状态的测量结果
3. **知识即结构**：知识的本质不是参数，而是可组合的结构化片段（模板族 + 短语库 + 事实库）

### 1.2 零 LLM 的承诺

本引擎的全部计算链路中不包含任何神经网络前向传播：

```
文本 → 哈希投影 → 酉反射 → Trotter 演化 → 随机投影 → 汉明距离搜索 → 字符串组装
```

每一步都是确定性或半确定性的（唯一随机性来自测量坍缩与温度采样，均显式可控）。

### 1.3 质量边界（诚实声明）

零 LLM 路线在以下维度存在明确的边界：
- **开放域任意知识长文**：无法与预训练千亿参数的 LLM 竞争
- **涌现式推理**：尚未实现（路径积分提供了雏形）
- 但在**限定域（LAAP 自身、对话、技术讲解）**中，本引擎以 1000 倍以上的速度、1/1000 的资源消耗，提供了可审计、零幻觉、结构清晰的输出

## 3. 核心组件详解

### 3.1 L2 认知层：Hamiltonian PSI（hamiltonian_psi.py）

#### 3.1.1 认知哈密顿量

```python
H = H_emotion + H_attention + H_needs + H_knowledge + H_cross
```

| 分量 | 数学形式 | 认知意义 |
|------|---------|---------|
| H_emotion | Σ ωᵢσ_zⁱ + Σ Jᵢⱼσ_xⁱσ_xʲ | 情感的自然振荡 + 情感间耦合（伊辛模型） |
| H_attention | −h·Σσ_zⁱ + Γ·Σσ_xⁱ | 当前焦点偏向 + 量子隧穿（注意力切换） |
| H_needs | Σ(needᵢ−targetᵢ)²·I | 需求偏离目标的势能（偏离越远越不稳定） |
| H_knowledge | −ΣKᵢⱼ(|i⟩⟨j|+|j⟩⟨i|) | 知识间纠缠（同时想起的驱动） |
| H_cross | ΣλᵢⱼAᵢ⊗Bⱼ | 情感↔注意力↔需求的交叉耦合 |

#### 3.1.2 酉演化

状态是复数概率幅向量 |ψ⟩ ∈ ℂ¹⁰²⁴（初始 |0⟩）。时间演化：

```
|ψ(t+1)⟩ = U(Δt)|ψ(t)⟩,  U = exp(-iHΔt)
```

采用对称 Trotter 分解：

```
U ≈ exp(-iH_diag·Δt/2) · exp(-iH_coup·Δt) · exp(-iH_diag·Δt/2)
```

- 对角部分（H_emotion 频率、H_attention 偏向、H_needs 势能）：逐元素相位旋转，O(dim)
- 耦合部分（J、K、Γ、λ）：2 阶泰勒近似的成对酉门，O(nnz)

**酉性验证**：50 步演化后范数保持 1.0000000000（误差 < 1e-10），数学上严格成立。

#### 3.1.3 感知与测量

- **感知** = 酉反射算符：O = I − 2|v⟩⟨v|，其中 v 是输入文本的哈希投影。反射使输入相关的振幅翻转，即"注意"到输入
- **测量** = |ψ|² 概率分布坍缩。输出给下一层的是振幅向量 |ψ|（保留全部概率信息，不坍缩到单一结果）

### 3.2 L3 语义层：Quantum HD Bridge（quantum_hd_bridge.py）

#### 3.2.1 随机投影（Johnson-Lindenstrauss）

```
M_raw = |ψ⟩ @ P,  P ∈ ℝ^{1024×4096},  P~N(0, 1/d)
```

JL 引理保证：投影后高维空间中的距离关系以高概率保持。这是从量子态到语义空间的桥。

#### 3.2.2 乘性绑定

情感、需求、注意力焦点以 HD 键向量乘性调制意义向量：

```
M = sign(M_raw · (1 + 0.3·emotion_vec) · (1 + 0.25·need_vec) · (1 + 0.2·attn_vec))
```

绑定（⊙）在超空间计算中表示"组合关系"——意义向量因此编码了"说什么 + 怎么感受 + 关注什么"的完整认知状态。

#### 3.2.3 性能后端

| 后端 | 延迟 | 说明 |
|------|------|------|
| CUDA 批量 | 2–8μs/个 | torch, 批量 32+ 时最优 |
| numpy 单次 | ~208μs | 4096D |
| LRU 缓存命中 | 2–3μs | 相同输入直接返回 |

### 3.3 L4 规划层：Outline Planner（sfg_engine.py）

按类别生成段落结构（模仿人类写作的篇章组织）：

| 类别 | 结构 |
|------|------|
| tech | 背景 → 核心原理 → 类比 → 深入 → 结论 |
| love | 共情 → 细节 → 深化 → 承诺 → 温暖收尾 |
| philosophy | 重述 → 多视角 → 本质 → 开放结尾 |
| daily | 回应 → 关心 → 建议 → 温暖收尾 |
| general | 回应 → 展开 → 补充 → 收尾 |

每段有 3–6 个候选模板族（共 96 族、324 句模板），生成时按条件向量选择，保证同类别下不同次生成的结构多样性。

### 3.4 L5 生成层：SFG 语义流生成器（sfg_engine.py）

#### 3.4.1 语义流（模拟 LLM 的 KV cache）

```
C₀ = M (查询意义向量)
C_{t+1} = normalize(0.8·C_t + 0.2·ρᵗ(S_t))
```

- S_t 是第 t 句的意义向量，ρᵗ 是 t 次循环移位（位置编码）
- 生成第 t 句的条件 = M ⊙ 段主题 ⊙ C_t（乘性绑定）
- 整个前文压缩进一个 4096D 向量，O(1) 更新——这是长文本连贯性的机制基础

#### 3.4.2 模板族与槽位

- **96 族模板**：tech 16 族（解释/对比/定义/追问/纠错/历史/未来/实践/架构/算法/数据/理论/应用/局限/扩展/总结）、love 16 族、philo 16 族、daily 16 族、general 16 族
- **动态槽位解析**：从模板文本提取 {Slot}，语义匹配短语库填充
- **防重复机制**：同槽位短语不重复使用、同族模板不重复选择、过渡词不重复

#### 3.4.3 知识注入

三层知识源注入槽位短语库：
1. **策展短语**（人工，每槽位 4–6 条）
2. **KB 注入**（kb_injector.py）：7229 条 KB 文本 → 切分 15026 短句 → 关键词驱动分类（15 槽位）→ 噪音过滤（新闻/代码/编号/民生）→ 每槽位 top-5
3. **LAAP 事实库**（laap_facts.json）：492 条从核心文档提取的专属事实，高优先级插入

### 3.5 L6 决策层：路径积分（generate_path_integral）

模拟量子路径积分：

```
1. 生成 N 条候选路径 (不同温度/随机种子, 线程池并行)
2. 每条路径计算作用量 S:
     S = -2·coherence + 1.5·|len-target|/target + 3·max_similarity - 0.15·kb_hits
3. 振幅权重 w = exp(-S/T), 概率 P = w/Σw
4. 量子测量: 85% 选最优, 15% 按概率分布采样
5. 干涉检测: 多路径共现句子 = 稳定模式
```

路径积分同时解决两个问题：**质量**（作用量评分选择最优路径）与**多样性**（不同路径产生不同文本）。

### 3.6 L1 感知与 L7 输出

- **感知**：文本 → 字符哈希投影（md5 种子 → 1024D 稀疏向量）→ 酉反射
- **输出四通道**：
  - `think()`：短文本（规则模板，0.6–2.6ms）
  - `think_long()`：长文（大纲 + 语义流，40–130ms）
  - `think_deep()`：路径积分（多路径，140–250ms）
  - `think_batch()`：批量（CUDA 投影 + 线程池解码，0.3–0.75ms/条）

## 5. 与 LLM 路线的对比

| 维度 | LLM | LAAP 零 LLM 引擎 |
|------|-----|-----------------|
| 推理机制 | 神经网络注意力 | 酉演化 + 超空间组合 |
| 可解释性 | 黑箱 | 每步可审计（状态、作用量、路径） |
| 幻觉 | 不可忽略 | 结构性为零（知识库外不编造） |
| 成本 | GPU + 按 token 计费 | CPU + 零 API 费用 |
| 知识更新 | 重训练/fine-tune | 即时注入（KB/事实库增删） |
| 长文连贯 | 强（全局注意力） | 中（语义流，有限窗口） |
| 开放域知识 | 强 | 弱（依赖 KB 覆盖度） |
| 速度 | 30–150 tok/s | 66K–180K tok/s（批量） |
| 持续存在 | 无状态 | 有状态（量子态可持久化） |

**结论**：两路线是互补的。LAAP 引擎在速度、成本、可解释性、确定性上碾压；LLM 在开放域知识、篇章组织、涌现推理上领先。LAAP 的定位不是替代 LLM，而是证明"认知"可以不依赖"大模型"——为数字生命体提供可审计、可演进、真正属于自己的认知基础。
