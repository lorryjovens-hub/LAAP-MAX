生成管线

从文本到页面的四步心跳

你不是在"写"页面——你只是在"选"积木。剩下的 HEP 替你完成。

PHASE 01

Intent Matching

自然语言 → 结构化 JSON Spec。纯关键词匹配，12 种页面类型，9 种风格，11 种内容领域。零 LLM，~0.1ms。

PHASE 02

Style Injection

匹配 Style Preset → 注入 CSS 变量体系。色板、字体、间距、阴影全部从预设中读取。~0.01ms。

PHASE 03

Component Assembly

从 HEP Registry 查询匹配组件 → 解析依赖树 → 拓扑排序 → 装配。全部白盒，可审计。~0.6ms。

PHASE 04

Zero-Token Generation

JSON Spec + CSS vars + 组件代码 → 纯字符串拼接 → 生产级 HTML。无 LLM，无概率，无幻觉。~2ms。

PHASE 05

Quality Gates

Emoji 检测（强制使用 Lucide SVG）、响应式断点覆盖、可访问性检查、性能评估。硬性门禁，不通过不出页。

PHASE 06

HEP Registry

每次新组件被创建 → 注册到 HEP Registry → 下次调用即可零成本复用。"编译一次，运行永远零成本"。

关键概念

两种"零 Token"的区别

这是 HEP 最容易被误解的地方——运行时零 Token ≠ 编译零成本。理解这个区别，你就理解了整个哲学。

运行时零 Token

HEP 保证的——ProductionComposer.from_spec() = 0 Token。纯字符串拼接，每次都是。你正在读的这个页面就是这样生成的。

确定性可审计每次 0

编译时 Token 消耗

模板本身是用 Token 写的——一次性的。写一个 Hero 模板可能花 200 Token，但这个模板可以用一万次，每次生成 0 Token。
